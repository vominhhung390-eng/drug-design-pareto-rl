# 四个正式RF性质预测器训练配置

正式生成前必须核验EGFR/VEGFR2历史固定模型，并从包内正式数据训练PARP1/BRD4。所有方法在同一靶点对上只能使用同一套oracle；不得让不同方法混用历史模型和恢复数据重训模型。

## 论文最终统一RF训练契约（四靶点共用）

PARP1/BRD4后期正式预测器与EGFR/VEGFR2采用相同的特征和RF训练参数；四个模型之间只更换靶点训练数据与标签，不更换模型超参数。

| 参数 | 四个靶点统一值 |
|---|---:|
| Features | chiral Morgan/ECFP4 |
| Radius | 2 |
| Bits | 2,048 |
| Include chirality | true |
| Model | `RandomForestRegressor` |
| n_estimators | 1,000 |
| max_features | 1.0 |
| min_samples_leaf | 1 |
| random_state | 0 |
| n_jobs | -1 |
| 其他模型参数 | scikit-learn默认值 |
| 对齐复现环境 | scikit-learn 1.7.2；RDKit版本写入输出metadata |

这套统一契约是论文正式复现参数。每个靶点仍须分别记录训练数据SHA-256、筛选规则、样本数和活性端点，不能因为超参数相同而合并训练数据。

### 早期POLYGON RF参考脚本（仅作来源记录）

入口：`POLYGON_original_RF_training_script.py`。该脚本用于追溯早期EGFR/VEGFR2实现，不替代上方论文最终统一训练契约。

| 项目 | 值 |
|---|---|
| 输入格式 | BindingDB TSV |
| 靶点过滤 | `UniProt (SwissProt) Primary ID of Target Chain` |
| 活性列 | IC50 (nM)、Kd (nM) |
| 同一行标签 | 取IC50/Kd可用值中的最小nM，再转 `-log10(M)` |
| 去重 | 按原始SMILES去重 |
| 指纹 | Morgan radius=2；RDKit默认2048 bits |
| 手性 | 原脚本未显式开启chirality；最终正式配置统一为true |
| 模型 | `RandomForestRegressor` |
| Trees | 1,000 |
| max_features / min_samples_leaf | 原脚本未显式设置；最终正式配置固定为1.0 / 1 |
| Random state | 0 |
| n_jobs | -1 |
| 训练方式 | 全量拟合；脚本未实际使用导入的train/test split或KFold |

### 当前复现边界

1. 当前恢复的JSON不是该脚本直接读取的原始BindingDB TSV；不参与训练的论文源XLSX已从精简包移出。
2. 当前目录名称已明确标记 `NOT_EXACT_ORIGINAL`，不能声称逐行重建最初训练数据。
3. 使用恢复数据重新训练EGFR/VEGFR2必须显式传入 `--allow-recovered-egfr-vegfr2`，输出metadata和SHA-256会将其标记为替代条件。

因此，EGFR/VEGFR2已具备固定模型输出级复现，但仍缺可哈希核对的精确原始训练行，不能声称从头训练级复现。

### 正式legacy-aligned RF配置

模型训练参数与上方EGFR/VEGFR2统一契约完全相同。`legacy-aligned`表示沿用第一靶点对的正式RF接口，而不是为PARP1/BRD4另设一套超参数。当前评价使用的活性阈值为pIC50 6.5；该阈值属于评价/命中判定规则，不是RF拟合参数。

论文正式默认命令（只重训PARP1/BRD4，EGFR/VEGFR2由 `models/oracles/` 提供）：

```powershell
python scripts/train_four_rf_predictors.py `
  --output models/reproduced_oracles
```

可选恢复数据重训命令：

```powershell
python scripts/train_four_rf_predictors.py `
  --allow-recovered-egfr-vegfr2 `
  --output models/reproduced_oracles
```

脚本直接读取精简包中的固定训练表，不依赖旧结果目录。PARP1/BRD4使用正式ChEMBL 37表；若启用恢复数据，EGFR/VEGFR2的非精确来源边界会写入输出metadata。

## 统一输出约定

训练脚本应生成：

```text
models/reproduced_oracles/
├── target_PARP1_model.pkl
├── target_BRD4_model.pkl
├── metadata.json
├── training_metrics.csv
└── SHA256SUMS.csv
```

只有启用 `--allow-recovered-egfr-vegfr2` 时，该目录才会额外生成
`target_EGFR_model.pkl` 和 `target_VEGFR2_model.pkl`；它们不是
`models/oracles/` 中历史模型的替代品。

`metadata.json` 必须记录数据哈希、过滤规则、指纹、scikit-learn/RDKit版本、全部RF参数和训练seed。
